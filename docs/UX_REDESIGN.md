# Интерфейс: обзор, ввод и источники — 2026-10-30

а не исследование пользователей или замер удобства. Mobbin в этой итерации не
использовался: поиск требовал платной подписки; владелец разрешил другой способ.

## Что изменилось

- **Здоровье**: компактные карточки сна/шагов, последняя известная дата каждого
  значения, свои показатели списком. Нет кнопки «Из API» и второго импорта внизу.
  Пустое состояние предлагает создать показатель, без демонстрационных записей.
- **Новая запись**: одна кнопка «Запись» → выбор показателя → только нужные поля.
  «Мои показатели → Добавить» создаёт определение, затем предлагает внести запись.
  Тип/способ дневного подсчёта выбираются компактными чипами. Архив сохранён.
- **Подробности**: период 7/30/всё время для сна и шагов, график, выбор дня и
  история. Добавление из выбранного дня сохраняет его дату в форме. Для своих
  показателей история стала LazyColumn; редактирование возвращает к форме сверху,
  действия записи — в меню. В интерфейсе видны названия источников, не их ключи.
- **Панели здоровья**: один ModalBottomSheet на весь сценарий, переходы меняют
  содержимое. Высота ограничена экраном и подстраивается под короткую форму.
  Сохранены общий запрет перетаскивания содержимого на iOS и явное закрытие.
  Страница и поля формы поддерживают saved state; числовой тип и ID редактируемой
  записи сохраняются, чтобы поворот Android не превращал изменение в дубликат.
- **Источники**: шесть показателей в одном списке. «Получить записи» при
  необходимости запрашивает системное разрешение, затем готовит предпросмотр
  за 30 дней. Отдельное «Сохранить в Lifety» подтверждает импорт. Для недоступных
  типов нет фиктивных нулей. Android умеет читать разрешённую часть выбора;
  если требуется установка Health Connect, доступен переход в магазин.
- **Ассистент**: вкладка «Данные» сразу показывает группы планирования, здоровья
  и остальных разделов. Предпочтения и ссылка находятся во вкладке «Разговор».
  Строка переключается целиком, имеет минимальную высоту 48 dp; сохранение внизу
  остаётся видимым при прокрутке. Данные не отправляются при изменении галочек.
- **Задачи**: даты свёрнуты в строки с текущими значениями; при раскрытии доступны
  прежние выбор даты/времени и удаление значения. Дополнительные поля не удаляются
  при сворачивании. Статус выполнения в новой задаче не занимает отдельную строку;
  у существующей он сохранён. Валидация дедлайнов и длительности прежняя.
- **Нижняя панель**: компактный список выбранных разделов, доступные отдельно,
  кнопка сохранения закреплена. Правила 1–5 и нативный UITabBar не менялись.

## Контракты и данные

Модели Task/Expense/HealthSnapshot/Person и старые методы репозиториев неизменны.
Схема SQLite по-прежнему **6**; миграция для этой итерации не нужна. Темы,
иконки приложения, защита разделов и настройки доступа ИИ сохранены.

`HealthMetricsRepository` дополнен методом
`importDeviceSamples(samples, source, baseline)` с default UnsupportedOperationException
для совместимости адаптеров. SQLDelight выполняет проверку baseline и запись
в healthSnapshot/healthMetric/healthEntry одной транзакцией. Ошибка любого типа
откатывает весь импорт. Не выбранные поля существующего снимка сохраняются.
Повторный импорт дневных итогов не создаёт дубликатов.

`MetricDeviceSource` теперь принимает sleep/steps вместе с прежними четырьмя
ключами. Android использует прежний AndroidHealthConnectGateway для сна/шагов;
iOS — прежний IosHealthSource и его объединение интервалов сна. HealthKit получает
единый запрос разрешений на выбранные типы, а алгоритмы чтения не дублируются.
Пустой результат Apple Health не трактуется как доказательство запрета доступа.

переход в Google Play, Android runtime, Android rotation/process-death, физический
iPhone и полный ручной CRUD с вводом текста. В Device Hub используется аппаратная
клавиатура; доступность сохранения с экранной клавиатурой требует отдельной проверки.
Сетевые LLM-запросы не выполнялись. Количественный замер плавности не проводился.
