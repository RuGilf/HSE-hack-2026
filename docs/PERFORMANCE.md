# Оптимизация переключения разделов — 31 октября 2026

Пользователь уточнил, что задержки сильнее всего заметны при переключении
разделов на iPhone. Изменение сохраняет модели, репозитории, schema 8,
дедлайны, категории, защиту и доступ к данным. Новых зависимостей нет.

## Изменения

1. Корневые вкладки и сегменты Плана на iOS переключают содержимое сразу,
   без crossfade двух полноразмерных экранов.
   Android сохраняет прежние переходы. Анимации sheets, стеклянной дуги,
   progress bars и графиков не отключались.
2. `LocalPlanningState` / `LocalNavigationState` / `LocalNavigationItems`
   теперь отслеживают конкретных читателей через compositionLocalOf.
   Стабильный retry callback и запомненный список routes больше не инвалидируют
   всё дерево приложения при изменении метаданных планирования.
3. FinancePresentation готовит сумму, категории, быстрые итоги и группы дат
   на Dispatchers.Default. LazyColumn получает готовые группы. Изменение
   даты/валюты не показывает старую сумму с новой подписью: расчёт имеет свой
   идентификатор, предыдущий результат сразу отсоединяется. Открытие формы не
   перезапускает расчёт неизменившихся расходов. Быстрым итогам не нужна сортировка.
4. iOS Finance больше не создаёт NSDateFormatter для каждой записи. Используется
   календарное преобразование с одним TimeZone на пакет. У отдельных native
   вызовов — worker-local cache TimeZone по системному ID. Ключ проверяется при
   вызове; сам FinanceContent каждый раз захватывает актуальный системный пояс.
   Это также избегает повторного чтения правил зоны в Kotlin/Native.
5. План дня, сортировка истории здоровья, недельные/месячные графики, сводка
   главной и проверки снимка ChatGPT рассчитываются вне главного потока.
   Отмена композиции отменяет публикацию результата; прежняя валюта/дата не
   подставляются в новый экран. Публичный порядок HealthRepository/HealthController
   не менялся.
6. Проверка конфликтов задач использует сортированные начала/окончания и
   двоичный поиск. После построения индекса каждый запрос O(log n), вместо
   просмотра всех остальных задач. Сохраняются half-open границы, неизвестная
   длительность, вложенные интервалы, наложения на фиксированное расписание.
7. График здоровья кеширует Path линий, точек и пропусков через drawWithCache.
   Выбор дня и reveal-анимация читают состояние в draw phase и не строят геометрию
   заново каждый кадр. Подробная история и все исходные записи сохраняются.
8. Сетка дня запоминает дорожки, группы и индекс задач. Верхняя iOS-панель,
   сегменты, tab bar, date picker и switches не применяют тот же appearance,
   шрифты, selection и цвета повторно. UISwitch больше не требует отдельный
   setNeedsLayout при каждом update. Смена темы остаётся реактивной.

Обоснование кеширования и переноса расчётов из композиции:
[Compose performance best practices](https://developer.android.com/develop/ui/compose/performance/bestpractices).
Поведение кеша графической геометрии:
[drawWithCache](https://developer.android.com/develop/ui/compose/graphics/draw/modifiers#drawwithcache).

## Измерения и границы

`IosFinancePerformanceTest` сравнивает старый formatter-путь и новый календарный
на одинаковых 1000 timestamps. Три прогона после разогрева, сравнивается результат
каждой записи; тест не содержит нестабильного порога по времени.
На iPhone 17 / iOS 26.5 Simulator, arm64 Debug Kotlin tests:

| Операция, 1000 записей | Медиана |
| --- | ---: |
| Прежний NSDateFormatter для каждой записи | 103.0655 ms |
| Календарь с повторным использованием зоны | 2.015375 ms |

Это измерение преобразования дат (~51×), **не** ускорение всего приложения
и не гарантия FPS на физическом iPhone. Полный raw-вывод находится в XML
`shared/build/test-results/iosSimulatorArm64Test/TEST-iosSimulatorArm64Test.ru.lifety.feature.finance.IosFinancePerformanceTest.xml`.
Повторные запуски дают другие абсолютные значения; эти числа — конкретный прогон.

Перед изменением приложения записан Time Profiler во время переходов
План → Финансы → Здоровье → Ассистент → Главная → План:
`/tmp/lifety-tabs-baseline.trace` (25 секунд). В main-thread стэках есть
инициализация UIDatePicker, FinanceContent, PlanTransferController и
NSDateFormatter._regenerateFormatter. AX-автоматизация и параллельная сборка
искажают нагрузку; trace используется для поиска работы, не для заявления
сравнимых до/после frame times. У Instruments был warning про таблицу без source;
CPU samples экспортировались успешно. Доказанного замера FPS нет.

## Как запускать на iPhone

В Xcode доступна дополнительная shared scheme **Lifety Performance**.
Она запускает Release без подключённого LLDB; обычная **Lifety** остаётся Debug.
Выберите свою Team и телефон как раньше, затем Lifety Performance → Run.
Сравнивать ощущение скорости следует на одном устройстве, одном наборе данных,
без параллельной сборки и без отладчика. Смена схемы не меняет данные приложения.

Терминал для simulator build:

```sh
xcodebuild -project iosApp/Lifety.xcodeproj -scheme 'Lifety Performance' \
  -configuration Release -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath /Users/rugilf/Documents/Codex/2026-10-25/e/work/performance-ios build
```

JDK/SDK — как в README; команды выполняются без LLM API-ключей.
