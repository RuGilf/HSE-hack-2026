# Подробное расписание дня

План → День по умолчанию открывает «По времени»; тот же переключатель возвращает
список. «Все даты», фильтры выполнения, календарь и люди сохранены.

## Работа с интервалами

- В редакторе: прежние дедлайн и начало, новая длительность 1..1440 минут,
  быстрые оценки 15/30/60/90/120 минут, необязательные шаги выполнения и связь
  с глобальной целью. «Выбрать время окончания» вычисляет длительность;
  время не позже начала означает следующий день, с учётом часового пояса/DST.
- Начало + длительность показывают точные дату и время окончания. Будущий
  дедлайн проверяется по **окончанию**, не только по началу. Дело с уже истёкшим
  сроком можно перепланировать, сохраняя пропущенный дедлайн.
- Задача и её TaskPlan сохраняются одной транзакцией в существующие таблицы.
  Оценка и шаги, полученные из ChatGPT, доступны для ручного редактирования;
  связь с целью сохраняется. Снятие даты не стирает оценку и шаги.
- Расписание сортируется по началу. Дело с дедлайном и временем показывается
  один раз; задачи только со сроком остаются отдельной группой.
  Работа через полночь видна на обоих соответствующих днях.
- Пересечения отмечены на обеих задачах. Их можно сохранить намеренно;
  интерфейс не переносит дела сам. Занятое время считается по объединению
  интервалов, без двойного счёта. Окончание после дедлайна отмечается отдельно.
- Без длительности задача остаётся точкой с подписью «Длительность не указана».
  Произвольная оценка не подставляется. Свободные окна при этом явно неполные.
- «Окна 8:00–22:00» позволяет менять часы поиска свободного времени.
  Дела за пределами окна остаются видимыми. Свободные промежутки от 15 минут
  открывают создание задачи с выбранным началом. На сегодня предлагается только
  оставшееся время, округлённое вперёд до 15 минут; на прошлые даты — без окон.
  Выбор часов/режима хранится в состоянии экрана, не является постоянным профилем
  рабочего дня после завершения процесса.

## Контракты

`Task`, `TaskPlan` и прежние repository APIs сохранены. В PlanningRepository
добавлен совместимый default `suspend saveTask(task: Task, details: TaskPlan?)`;
SQLDelight production implementation сохраняет обе записи атомарно. Другие
реализации по умолчанию сообщают, что ручное планирование недоступно.
Schema остаётся v5, миграции не нужны. Новый общий расчёт —
`core/planner/DayTimeline.kt`, UI — `feature/tasks/DayTimelineContent.kt`
и `TaskDurationFields.kt`. Публичные screen/route signatures прежние.

## Проверка

Общие тесты: пересечения/касающиеся интервалы, объединение занятости, неизвестная
длительность, полночь, 23/25-часовые дни, конец относительно дедлайна, выбор конца
через полночь/DST, исключение прошедших свободных окон. SQLite host test проверяет
атомарность валидации, сроки, связь с целью/шаги и восстановление после открытия
файловой БД. На iPhone Simulator существующей QA-задаче задано 09:00 + 30 минут,
после сохранения показан интервал 09:00–09:30; после завершения процесса и нового
запуска время и длительность восстановились. Создание по свободному окну открылось
с соответствующим началом и отменено без записи. Пересечения и DST вручную
на устройстве не создавались — проверены расчётами. Физические устройства,
iPad и Android runtime в этом обновлении не проверены.
