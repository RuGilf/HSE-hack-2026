# Код-пароль на разделы

Настройки → «Код-пароль на разделы»: выбрать разделы, задать шестизначный код,
повторить его и сохранить. Один код используется для всех выбранных разделов.
Выбор не включает защиту до явного сохранения. Смена кода, изменение списка и
отключение защиты требуют текущего кода, даже в уже открытой сессии.

После успешного ввода выбранные разделы доступны до ухода приложения в фон /
потери активности. Есть «Заблокировать сейчас». После нового запуска код
запрашивается заново; открытая сессия не сохраняется. Из защищённого редактора
можно выйти назад, не вводя код.

## Общие данные

План включает календарь, людей, цели и редактор задач. Если защищены План,
Финансы или Здоровье, Главная и Ассистент также требуют код, потому что выводят
общие сведения. Данные закрытого раздела не остаются видимыми на главной или
в сохранённом представлении ассистента. Остальные выбранные разделы блокируются
напрямую по своим route IDs. Встроенный API-чат при блокировке удаляется из
composition, его controller закрывается и отменяет текущую операцию.

## Хранение и ограничения

- Сам код не записывается: случайная соль 16 байт, PBKDF2-HMAC-SHA1,
  1 300 000 итераций, verifier 32 байта. Выбор алгоритма одинаков после
  обновления ОС, включая minSdk 24. Вычисления/операции хранилища — вне UI-потока.
- iOS хранит настройки и verifier отдельно от API-ключа в Keychain service
  `ru.lifety.ios.section-lock`, с `WhenUnlockedThisDeviceOnly`.
  [Apple Keychain](https://developer.apple.com/documentation/security/keychain-services).
- Android хранит конфигурацию в AES-GCM ciphertext, ключ — Android Keystore,
  preferences `lifety-section-lock`. Используются отдельные ключ/namespace.
  [Android Keystore](https://developer.android.com/privacy-and-security/keystore).
- После пяти неверных попыток ввод блокируется на 30 секунд; последующие
  неверные попытки увеличивают паузу до 5 минут. Счётчик и срок сохраняются
  между запусками. Успешная проверка сбрасывает их. Ошибка чтения/записи не
  отключает защиту; приложение показывает повторную попытку чтения.
- Уход в фон во время проверки не открывает следующую сессию: контроллер
  сверяет номер сессии после завершения операции. Настроечная панель закрывается,
  незаписанные цифры не остаются в UI и не попадают в rememberSaveable/clipboard.
- Конфигурация не входит в Repositories, agent workspace, JSON для ChatGPT
  или экспорт плана. Схема SQLite и бизнес-модели не менялись.

Это **блокировка экранов**, не шифрование SQLite и не замена кода устройства.
Она не защищает копии/текст, которые пользователь уже экспортировал. Нет
восстановления забытого кода, биометрии или независимого кода для каждого раздела.
Защита по умолчанию выключена. Пользователь сам задаёт свой код на устройстве.

## Проверка

Семь общих тестов контроллера: настройка/восстановление, зависимости агрегированных
разделов, неверные попытки/пауза через перезапуск, смена/отключение только со старым
кодом, уход в фон во время проверки, ошибки/повреждение хранилища без обхода защиты.
Общий набор выполняется и на JVM, и на iOS Simulator.

Swift-реализация CommonCrypto отдельно выполнена на macOS из исходника
`KeychainStore.swift` с тестовыми protocol stubs: результат совпал с известным
PBKDF2-вектором Python hashlib; проверены неверный код, некорректная соль и
уникальные случайные соли. Чтение/запись Keychain этим smoke test не заменяются.

На iPhone 17 / iOS 26.5 Simulator вручную проверены вход в настройки, список
разделов, пустая цифровая клавиатура, отмена без установки кода и отсутствие
ошибки при первоначальном чтении Keychain. Код через интерфейс не устанавливался;
полный UI-цикл разблокировки/смены/отключения и реальный lifecycle с активной
защитой на устройстве не проверены. Физические устройства, iPad и Android runtime
не проверены. Команды общих сборок/тестов — в README.
