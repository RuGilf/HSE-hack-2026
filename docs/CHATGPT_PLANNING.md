# Постоянный разговор с ChatGPT и план Lifety

## Как пользоваться

1. В «Плане» создайте задачи и дедлайны. На главной добавьте глобальные цели.
2. Откройте **Ассистент**. По умолчанию это экран ручного обмена, без API-ключа.
   В шестерёнке «Настройки обмена» задайте постоянные предпочтения: рабочие часы,
   перерывы, доступное время. При желании добавьте личную ссылку на существующий
   разговор `https://chatgpt.com/c/…` (также поддержан `/g/…/c/…`). Публичная
   ссылка `/share/…` для этого не подходит. Открытие ссылки не отправляет сообщение.
3. Добавьте пожелания к конкретному плану и нажмите **«Подготовить первый запрос»**.
   Он содержит начальные правила, ваши предпочтения и полный компактный снимок.
4. **«Скопировать запрос»** или **«Скопировать и открыть разговор»**. Вставьте его
   в один постоянный разговор ChatGPT самостоятельно. Можно использовать проект
   ChatGPT и хранить постоянные инструкции там. «Поделиться» остаётся альтернативой,
   но не гарантирует выбор существующего чата. Автоматической отправки нет.
5. После отправки нажмите **«Я отправил · жду ответ»**. Только эта отметка меняет
   базу сравнения отправок; открытие меню/копирование не считаются доставкой.
   Подготовленный текст и ожидание сохраняются после перезапуска приложения.
   Форма подготовки сворачивается; при ожидании главное действие — вставить ответ.
   «Пожелания» снова открывает форму, быстрое обновление доступно без её раскрытия.
6. Следующий **«Обновить контекст»** (либо «Подготовить обновление» в форме) содержит полный актуальный компактный
   снимок плюс количества новых/изменённых/выполненных или удалённых задач и
   изменений целей относительно последней подтверждённой отправки. Предпочтения
   повторяются лишь после изменения. «Запрос для нового разговора» снова включает
   полную начальную инструкцию; чат ChatGPT эта кнопка сама не создаёт.
7. Обсудите план в ChatGPT. Когда готовы, скопируйте его итоговый структурированный
   ответ и нажмите **«Вставить ответ ChatGPT»**. Разбор и предпросмотр запускаются
   сразу. Есть ручное поле и импорт UTF-8 JSON/текстового файла до 1 МБ.
8. Предпросмотр показывает прежнее/новое время, оценку, дедлайн, шаги и очередь.
   Только **«Применить план»** меняет данные. Текущий план, длительности и причины
   очереди появляются в ассистенте; расписание — в Плане и календаре.

API-подключение сохранено: **Ассистент → Настройки обмена → Дополнительно →
Встроенный чат · подключение API**. У встроенного чата есть возврат «План с ChatGPT».
Доступ встроенного API к данным независим от ручного экспорта.

Это ручной обмен текстом/файлом. Lifety не входит в аккаунт ChatGPT, не читает
его переписку и не гарантирует открытие ссылки именно в установленном приложении:
обработчик HTTPS выбирает ОС. Нативного приёма через Share Extension пока нет.

## Сон: меньше контекста, без потери свежих данных

По умолчанию сон **не включён**. В настройках обмена его можно добавить отдельно.
Весь расчёт выполняется на устройстве:

- Последние **7 календарных дней**, включая сегодня, в часовом поясе устройства:
  дата и длительность сна. Пропуск — `null`, реальный записанный ноль остаётся нулём.
- Для **каждого месяца с известным сном**: медианная длительность в минутах,
  число известных дней, число дней в месяце, признак текущего незавершённого месяца.
- Несколько записей одного дня не суммируются: используется последнее известное
  значение сна. Более поздняя запись только шагов не стирает известный сон.
- При чётном числе дней медиана — среднее двух центральных значений, в том числе
  половины минуты. Пустые месяцы не получают выдуманную медиану. Будущие записи и
  значения вне диапазона 0–1560 не учитываются. Малое число известных дней видно
  явно; незавершённость месяца отличается от пропусков измерений.
- В экспорт не входят сырые timestamps, вся дневная история, шаги, финансы,
  карточки людей, API credentials или медицинские выводы.

За 365 дней это 7 дневных строк и 12–13 месячных сводок, вместо 365 измерений.
Результат имеет дату/часовой пояс; месячные медианы не объявляются реальными
затратами времени или достоверным измерением энергии. При выключении сна
подготовленный текст удаляется, ожидаемый ответ становится неактуальным.
База сравнения отправок хранит только задачи/цели/оценки, без сводки сна и текста
постоянных предпочтений. Подготовленный текст с выбранными данными хранится локально.

## Формат и проверки

Новые запросы содержат контекст `lifety-context-v2` и просят ответ `lifety-plan-v2`:

```json
{
  "format": "lifety-plan-v2",
  "baseSnapshot": "точное значение из запроса",
  "requestId": "точное значение из запроса",
  "summary": "Объяснение порядка и оценок",
  "tasks": [{
    "taskId": "реальный ID задачи",
    "scheduledAt": "2026-10-29T18:00:00+03:00",
    "durationMinutes": 60,
    "approach": "Конкретные шаги",
    "goalId": null
  }],
  "deferredTasks": [{
    "taskId": "ID другой задачи",
    "reason": "Не помещается в доступное время"
  }]
}
```

Это пример формы, не стартовые пользовательские данные.

- Каждая текущая незавершённая задача ровно один раз: расписание или очередь.
  Неизвестные, повторные, завершённые и пропущенные ID отклоняются. Новые задачи
  не создаются. Допустим план целиком из очереди с объяснениями.
- В очереди снимается прежнее `Task.scheduledAt`. Название, дедлайн, завершение,
  прежние оценки/подход/связь с целью сохраняются. Причина — непустая, до 500 символов.
- Начало в будущем (до пяти лет), ISO 8601 с явным offset, длительность 1–1440 минут,
  шаги до 2000 символов. Слоты не пересекаются, работа заканчивается до будущего
  дедлайна. Просроченный дедлайн сохраняется, перепланировать выполнение разрешено.
- `goalId` — активная существующая цель или null; `summary` — до 6000 символов.
- Полный JSON, необязательная Markdown-обёртка, до 1 млн символов / 1 млн байт файла.
  Пользователь видит «ответ», технический JSON-формат уже включён в запрос.
- `baseSnapshot` проверяет свежесть всех задач/целей/оценок; FNV-64 — fingerprint
  свежести, не механизм аутентификации. `requestId` должен совпасть с подготовленным
  или последним подтверждённым ожидающим запросом. Изменение дня/часового пояса,
  предпочтений, разрешения сна или самой сводки требует обновить запрос.
- Проверки выполняются перед предпросмотром и **внутри транзакции применения**.
  Слоты, очередь, report и квитанция обмена сохраняются атомарно. Повторное применение
  ответа v2 после успешного импорта отклоняется. Импорт v2 сам подтверждает отправку
  соответствующего запроса, если пользователь пропустил ручную отметку.
- Старые `lifety-plan-v1` совместимы: для них прежнее правило каждой актуальной
  задачи в расписании, без очереди/requestId. Их проверка свежести касается
  Task/Goal/TaskPlan; сводки сна в старом формате не было.

## Контракты и хранение

- SQLDelight schema **v5**, migration `4.sqm` добавляет singleton `chatGptExchange`.
  Старые миграции и таблицы сохраняются; Task/Expense/Health/Person/Goal не менялись.
- `Repositories.chatGptExchange: ChatGptExchangeRepository? = null` — additive DI.
  Интерфейс: `observe(): Flow<ChatGptWorkspace>`, `savePreferences`, `saveDraft`,
  `markSent(draftId, now)`. Production подключает общий driver `lifety.db`.
- `core/planning/ChatGptContext.kt`: локальная сводка сна, компактный baseline,
  сравнение отправок, preferences/draft/sent/receipt, подготовка initial/update,
  guard контекста и проверка безопасного личного URL.
- `ImportedPlan` дополнен default-полями `deferredTasks = emptyList()`,
  `requestId = null`; прежние конструкторы и ответы v1 остаются совместимы.
- `SqlDelightPlanningRepository.apply` сохраняет сигнатуру и атомарно проверяет
  также текущую сводку здоровья и состояние обмена для v2.
- `PlanTransferController` наблюдает данные через Flow, хранит preview в памяти,
  различает подготовку / копирование / подтверждение отправки / применение.
  Перед передачей текста повторно проверяется свежесть; изменение пожеланий
  блокирует отправку старого подготовленного текста до новой подготовки.
- Пять разделов, screen signatures, темы/иконки и существующий API-чат сохранены.

## Проверено

- `:androidApp:build`: debug/release и lint — успешно.
- `:shared:testAndroidHostTest`: 217 прошли, 6 live LLM пропущены без credentials.
- `:shared:iosSimulatorArm64Test`: 104 прошли. Всего **321 прошедшая проверка**.
- Тесты: 365 дней → 7 дней + месячные медианы; последний сон на день, null/ноль,
  чётная/нечётная медиана, високосный февраль, часовой пояс, пропуски, future rows;
  initial/update с полным снимком и изменениями; opt-in и безопасные ссылки;
  восстановление draft/ожидания, отказ устаревшего сна внутри транзакции,
  сохранение очереди/дедлайнов/оценок, requestId, запрет replay, миграции в v5;
  полный цикл контроллера prepare → handoff → acknowledgement → preview → apply.
- Xcode Debug / iOS Simulator arm64: `BUILD SUCCEEDED`.
- На iPhone 17 / iOS 26.5 Simulator проверены: основной экран без API, настройки
  обмена и opt-in сна, подготовка запроса, сводка 7 дней / медиана / coverage,
  отметка «Я отправил», восстановление запроса/ожидания после завершения процесса,
  копирование и вставка, понятный отказ при вставке запроса вместо ответа,
  Share/Files и возврат после отмены, дополнительный API-чат и возврат к обмену.

Не проверены реальный аккаунт/установленное приложение ChatGPT, открытие личного
разговора после входа, физический iPhone, интерфейс Android на устройстве и выбор
настоящего файла в iOS Files. Корректный импорт v2, предпросмотр и применение
проверены автоматическими тестами контроллера/SQLite; полный успешный импорт через
GUI симулятора не подтверждён. Внешних отправок и live LLM запросов не выполнялось.
