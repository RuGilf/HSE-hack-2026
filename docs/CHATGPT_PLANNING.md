# Обмен планом с ChatGPT, глобальные цели и новая главная

## Как пользоваться

1. Создайте задачи в «Плане», расставьте дедлайны. На главной откройте
   «Глобальные цели → Все», добавьте желаемый результат, описание и необязательный срок.
2. «Ассистент → шестерёнка ассистента → Экспорт / импорт с ChatGPT».
   API-ключ для этого обмена не нужен.
3. «Подготовить для ChatGPT → Поделиться». Откроется системное меню iOS/Android.
   Выберите ChatGPT, если он доступен в меню; иначе «Скопировать» и вставьте текст
   в нужный разговор самостоятельно. Экспорт содержит задачи/дедлайны, активные
   цели, текущие оценки времени, часовой пояс и инструкцию вернуть совместимый JSON.
4. Обсудите с ChatGPT доступное время и оценки. Его финальный ответ должен быть
   JSON `lifety-plan-v1`. Скопируйте ответ или сохраните JSON-файл.
5. Вернитесь в тот же экран Lifety: вставьте ответ (кнопка «Вставить» или системная
   вставка) либо выберите UTF-8 JSON/текстовый файл до 1 МБ. «Проверить и посмотреть»
   показывает прежнее/новое время, длительность, дедлайн, шаги и связь с целью.
6. Только «Применить план» изменяет расписание. Все изменения сохраняются одной
   транзакцией. День/календарь показывают новое время; карточки — длительность,
   редактор задачи — подробные шаги. Исходные дедлайны, названия и статусы сохраняются.

Это ручной обмен текстом/файлом через системное меню, без входа в аккаунт ChatGPT,
автоматической синхронизации переписки и OpenAI API. Доставку в конкретное
приложение выбирает пользователь. Внутри приложения нет встроенного ChatGPT.

## Что проверяет импорт

- Формат/обязательные поля, размер до 1 млн символов (файлы — 1 млн байт),
  полный JSON с необязательной Markdown-обёрткой.
- Каждая текущая незавершённая задача ровно один раз; неизвестные, повторные,
  завершённые и пропущенные ID отклоняются. Новые задачи из ответа не создаются.
- Начало в будущем (до пяти лет вперёд), ISO 8601 с явным UTC offset;
  длительность — целое 1–1440 минут, шаги — непустой текст до 2000 символов.
- Работа должна закончиться до ещё не истёкшего дедлайна; задачи не пересекаются.
  Для просроченного срока перепланирование разрешено, прежний дедлайн сохраняется
  и выделяется в предпросмотре. Несовместимый план нужно обсудить с ChatGPT и исправить.
- `goalId` — существующая активная цель либо null.
- `baseSnapshot` совпадает с текущим снимком задач/целей/оценок. Снимок проверяется
  и перед предпросмотром, и внутри транзакции применения. Если данные изменились,
  требуется новый экспорт. FNV-64 fingerprint служит проверке свежести, не аутентификации.
- Оценки времени и рекомендации не считаются измеренной работой или достоверными
  фактами. Разбор `summary` ограничен 6000 символами.

Пример формы ответа (значения должны соответствовать реальному экспорту):

```json
{
  "format": "lifety-plan-v1",
  "baseSnapshot": "точное значение из экспорта",
  "summary": "Объяснение выбранного порядка и оценок",
  "tasks": [{
    "taskId": "реальный ID из экспорта",
    "scheduledAt": "2026-10-28T09:00:00+03:00",
    "durationMinutes": 60,
    "approach": "Собрать материалы, сделать структуру, подготовить черновик",
    "goalId": null
  }]
}
```

Пример не является стартовыми данными или планом реального пользователя.

## Цели и агент

Цели сохраняются локально: название, описание, срок, статус достижения. Их можно
редактировать и удалять с подтверждением. Удаление цели не удаляет задачи;
связь с целью очищается. Привязку задач к целям можно получить через импорт плана.
На главной у связанных целей показывается прогресс по завершённым задачам.

В ассистенте видны дата и объяснение последнего импортированного плана.
При включённом доступе «Задачи, цели и план» перед каждым сообщением обновляются
`data/tasks`, `data/goals`, `data/taskPlans` и `data/planning/report.json`.
Старый summary — историческое объяснение: текущие записи имеют приоритет.
При выключенном доступе эти источники отсутствуют. Заметки о людях, финансы,
здоровье и credentials в ручной экспорт не включаются.

## Хранение и границы

SQLDelight schema v4; `3.sqm` добавляет `goal`, `taskPlan`, `planReport`.
Миграции 1/2 сохранены, прежние данные остаются. Публичные Task/Expense/Health
модели и методы репозиториев не менялись. В DI добавлены nullable default-поля
`goals` и `planning`; production всегда подключён к общей `lifety.db`.
Удаление задачи убирает её TaskPlan; удаление цели очищает goalId.

Новый обзор ограничен по ширине на больших экранах. Показатели расположены
парами, цели — в горизонтальной ленте, план — короткими строками. Дублирующая
кнопка «Спросить Lifety» удалена. Пять разделов и нативное стекло iOS сохраняются.
Дизайн сделан по требованиям пользователя и текущей теме, без референсов Mobbin
(поиск недоступен по тарифу).

  системное меню «Поделиться», открытие/отмена выбора файла, копирование/вставка,
  ошибка неверного ответа и прокрутка после возврата из системных окон.

  вызываются из обычного окна приложения, исключая окно клавиатуры.

Не проверены физический iPhone, интерфейс Android на устройстве, передача
в установленный ChatGPT и выбор настоящего JSON-файла через iOS Files.

с временной SQLite, включая сохранение после повторного открытия базы.
Live LLM тесты намеренно не запускались; автоматического обмена с аккаунтом нет.
