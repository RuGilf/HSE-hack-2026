# Дневной план и дедлайны

26 октября 2026. Общий Compose UI для Android и iOS.

## Работа с планом

План → **День** показывает выбранную дату. Стрелки переключают день, кнопка даты
открывает календарь выбора. «Сегодня» возвращает к текущей дате. «Все даты»
показывает прежний общий список, включая завершённые записи без даты.
Фильтры «Актуальные / Завершённые / Все» сохранены.

Дневной список делится на:

- **Просроченные** — невыполненные дела с истёкшим сроком. Старые сроки включаются
  в план сегодняшнего дня; на других датах нет отдельного переноса просрочки.
- **Дедлайны на выбранную дату** — активные дела с окончанием в этот день.
- **Запланировано** — активные дела с временем выполнения в этот день, если они
  уже не показаны в двух предыдущих группах.
- **Без даты** — сегодняшний доступ к активным делам, у которых нет ни времени
  выполнения, ни дедлайна. Эти дела не выдаются за запланированные на будущую дату.
- **Завершённые** — соответствующие выбранной дате по расписанию или дедлайну.
  В модели нет completedAt, поэтому дата фактического завершения не выдумывается.

Одно дело появляется в дневном списке один раз. Если выполнение назначено сегодня,
а срок завтра, дело видно сегодня в расписании и завтра среди дедлайнов. Общий
календарь по-прежнему учитывает обе даты, не дублируя одно дело внутри дня.

## Редактор

Дедлайн расположен сразу под названием. Можно выбрать «Сегодня», «Завтра» или
произвольную дату и отдельно указать время. Для нового срока дата без уточнения
времени означает **23:59**. Изменение даты существующего срока сохраняет выбранное
время; отмена DatePicker/TimeInput не меняет значения. «Убрать» снимает срок.

«Когда заняться» — отдельное необязательное время в расписании. Оно не нужно
для сохранения дедлайна. Создание из конкретного дня предлагает выполнение в
09:00 выбранной даты, как и создание из календаря; из «Все даты» время не назначено.
Дедлайн не устанавливается автоматически — только после действия пользователя.

Время выполнения позже ещё не наступившего дедлайна подсвечивается рядом с полем
срока и кнопкой сохранения; такая комбинация отклоняется также в ViewModel. Уже
просроченное дело можно перепланировать, сохранив первоначальный пропущенный срок.
На завершённые задачи ограничение порядка дат не распространяется. Ранее
сохранённые записи не переписываются. Срок в прошлом допускается, чтобы можно
было учесть и затем исправить просрочку. Несуществующее локальное время при DST
отклоняется, включая пропущенную календарную дату.

В карточках видны срок, время выполнения и просрочка. Статусы и текущий день
обновляются каждые 30 секунд, пока экран открыт. Модели Task, repository interfaces,
SQL schema и root routes не менялись, миграция БД не требуется.

## Изменённые файлы

- `core/planner/DayPlan.kt`: группировка, civil date/time и проверка порядка дат.
- `feature/tasks/TasksScreen.kt`: обзор дня, выбор даты, группы и общий список.
- `feature/tasks/TaskDateTimeField.kt`: явная дата/время, быстрые действия, удаление.
- `feature/tasks/TaskEditorScreen.kt`, `TaskEditorViewModel.kt`: редактор и валидация.
- `core/ui/TaskCard.kt`: отображение срока и актуальной просрочки.
- `feature/calendar/CalendarScreen.kt`: обновление времени статусов.
- `app/PlanScreen.kt`: вкладка «День» вместо прежнего названия «Задачи».
- `commonTest/core/planner/DayPlanTest.kt`: 7 сценариев дат, группировки и валидации.

Пути Kotlin указаны относительно `shared/src/commonMain/kotlin/ru/lifety/`;
тест — относительно `shared/src/commonTest/kotlin/ru/lifety/`.

## Проверка

```sh
./gradlew :androidApp:build :shared:testAndroidHostTest :shared:iosSimulatorArm64Test
```

JDK/Android SDK — как в README. Android debug/release + lint, host tests и native
Kotlin iOS tests успешны: **155 host tests passed**, 6 live LLM tests skipped без
ключей; **61 iOS test passed**, без failures/errors. Семь новых тестов проверяют
группировку без дублей, перенос просрочки, недатированный backlog, границы локального
дня, равенство дедлайна текущему моменту, DST/пропущенные даты и порядок дат.

Xcode simulator build — успешно. На отдельном iPhone Simulator вручную проверены
установка/изменение дедлайна, выбор времени, сохранение дела только с дедлайном,
отображение в дневном списке и календаре, сохранность после перезапуска приложения.
При выполнении позже будущего срока видны объяснение и недоступная кнопка
сохранения; удаление времени выполнения снова разрешает сохранение.
Тестовые записи — только в QA simulator.
Проверка настоящего телефона и системных уведомлений в эту работу не входит.
