# Локальная песочница агента

Отдельный браузерный пульт для проверки настоящего Kotlin-ядра. В APK ничего не
добавляет. Сервер работает только на 127.0.0.1, без LAN/CORS; API-ключ остаётся в
процессе JVM. На клиент он не передаётся. Генерационные лимиты в LLM API не задаются.

Запуск из PowerShell с JDK 21 и установленным Android SDK:

```powershell
& .\shared\src\androidHostTest\kotlin\ru\lifety\feature\assistant\agent\playground\start.ps1
```

При необходимости задайте JAVA_HOME и ANDROID_HOME. Скрипт спросит ключ скрытым
вводом, если LIFETY_LLM_API_KEY не задан в окружении. Base URL и модель берутся из
LIFETY_LLM_BASE_URL / LIFETY_LLM_MODEL; дефолты — localhost:20128/v1 и
antigravity/gemini-3.8-flash-high. Откройте напечатанный HTTP-адрес.

Остановка: тот же скрипт с `-Stop`. `-PrepareOnly` только компилирует и готовит
classpath. Gradle используется для сборки существующего host-кода, затем отдельная
JVM работает без удержания Gradle. Проектные JAR/классы копируются в отдельный
runtime-каталог, чтобы JVM не блокировала их следующую пересборку на Windows.
Можно задать `-Port 56996`, чтобы сохранить адрес после остановки/запуска.
Init-script/classpath/logs создаются в ignored
build/agent-playground; файлы конфигурации проекта и Manifest не меняются.

Стартовый набор: 29 вымышленных расходов (RUB + USD), 6 задач, последний снимок
здоровья и отдельный CSV с 14 днями сна/шагов. Каждый источник помечен synthetic.
Три in-memory репозитория реализуют обычные интерфейсы, AppContainer/lifety.db не
подключаются. Дополнительный CSV — ручной демо-импорт, не Health Connect sync.

Попробуйте:

- Разобрать траты за неделю, написать скрипт и сохранить отчёт; открыть scripts/
  и reports/ во вкладке «Файлы».
- Попросить создать задачу; до «Применить» она не появится в данных.
- Попросить запомнить предпочтение, подтвердить его, начать новый диалог и спросить
  о предпочтении. Долгосрочная память/файлы сохраняются.
- Разобрать CSV сна/шагов, дать собственный дополнительный текст в сообщении.

Видны реальные tool calls/results. Чат и содержимое файлов отображаются как текст.
«Сбросить демо» очищает память, чат и файлы, восстанавливает начальные записи.
Все изменения репозиториев в памяти исчезают при перезапуске JVM; рабочие файлы и
память сохраняются в build/agent-playground/session до явного сброса.
Удаление факта очищает производные файлы и чат; затем восстанавливаются только
независимые синтетические CSV/описание набора. Частные заметки не возвращаются.
